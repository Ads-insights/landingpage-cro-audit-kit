## Why a Skill Per Page-Type Changes Everything

Most CRO audits treat every page the same. Same checklist for a B2C product page and a B2B SaaS demo LP. Same questions for a checkout flow and an about page. The result: generic findings, missed leverage, recommendations that fit no page particularly well.

**This kit takes the opposite approach.** Every page-type gets its own dedicated audit skill — built on the conversion levers that actually matter for *that specific page* on *that specific business model*.

A B2C ecom product page audit zooms in on add-to-cart friction, review prominence, mobile PDP density, urgency calibration. A B2B SaaS demo LP audit zooms in on message-match with the ad source, lead-magnet value-equation, BANT form calibration, single-CTA dogma. A B2B about page audit zooms in on supplier-credibility, named leadership, vendor-due-diligence signals. **None of these audits would make sense applied to the wrong page.**

That's why this kit has **22 separate skills** instead of one universal auditor. Each one is calibrated end-to-end:

- 🎯 **Page-specific framework** — 11 finding categories tailored to that page's conversion job
- 🧭 **Business-model calibration** — B2C ecom vs B2B SaaS vs leadgen consultancy get different lenses
- 📚 **Source-backed recommendations** — Baymard, Cialdini, MECLABS, ConversionXL, Forrester, Edelman B2B Trust, Hormozi, April Dunford, Challenger Sale — each cited per finding
- 🔬 **Test-ready findings** — every recommendation comes with a hypothesis, primary metric, expected impact range, and ICE score

This is the difference between *"add some social proof"* and *"add aggregate review-rating directly under product-title above-the-fold, expect +15-30% on add-to-cart rate, primary metric ATC-rate, source: Spiegel Research Center"*.

**Generic CRO advice is everywhere. Specificity is rare.** This kit is specificity, productised.

## Key Features

🎯 **Page-type calibrated** — A B2B SaaS demo page and a B2C ecom checkout get audited with completely different lenses. No generic recommendations applied where they don't fit.

🔬 **Evidence-backed** — Every finding cites a specific CRO principle: Baymard form research, Cialdini's reciprocity, ConversionXL message-match, Edelman B2B Trust Barometer, Forrester B2B buyer research, MECLABS Conversion Sequence Heuristic, Hormozi value-equation, and more.

📊 **ICE-scored prioritisation** — Every finding gets Impact, Confidence, and Ease scores. Sorted by ICE descending within each priority tier. Sprint-ready out of the box.

📄 **Client-ready exports** — Word documents for stakeholder presentations, Excel spreadsheets for sprint planning. Both generated on request, both branded clean.

🌍 **Multilingual** — Auto-detects page language (NL/DE/FR/ES/IT/EN) and delivers the entire audit in that language.

🧠 **Honest by design** — Never claims a missing element exists. Never invents customer reviews or fabricates metrics. Acknowledges when something can't be assessed from the screenshots provided.

🛡️ **Hard safeguards** — Visual verification rules prevent fabricated findings. Authenticity restraints prevent risky claims about photos, certifications, or customer logos. Financial disclosure restraints prevent harmful recommendations for B2B about pages.

## Quick Start

> **Requires a Claude Pro, Team, or Enterprise subscription.** Skills are not available on the free plan.

### 1. Install the skills

Go to **[claude.ai](https://claude.ai)** → **Customize** → **Skills**

Each skill in this repository lives in its own folder, containing a `SKILL.md` and a `references/` folder with supporting files. To install a skill in Claude:

1. **Clone or download this repository** (or download a specific skill folder)
2. **Zip the skill folder** (e.g. `landingpage-b2c-ecom-productpage/` → `landingpage-b2c-ecom-productpage.zip`)
3. In Claude: click the **+** button → **Upload a skill** → select the `.zip` file
4. Save

**Install all 22 for full coverage**, or pick only the skills relevant to your work — each skill is fully self-contained.

**Tip:** if you only need a few skills, download just the folders you need. The references inside each folder are required for that skill to work correctly.

### 2. Pick the right skill for your page

Use the [Skill Matrix](#the-skill-matrix) above. Match by page-type (homepage, product, checkout, etc.) and business-model (B2C/B2B × ecom/leadgen).

Examples:
- Auditing a webshop product page? → `landingpage-b2c-ecom-productpage`
- Auditing a SaaS demo landing page from a LinkedIn Ads campaign? → `landingpage-b2b-leadgen-dedicatedlp`
- Auditing a B2B about page for vendor due diligence? → `landingpage-b2b-leadgen-aboutus`

### 3. Run the audit

Drop the skill name + URL into Claude:

```
Use landingpage-b2c-ecom-productpage on https://example.com/product/xyz
```

Claude will ask for screenshots (mandatory — the skills won't audit without visual evidence). Upload them and the audit runs automatically.

**Output:** structured audit in chat, plus optional `.docx` and `.xlsx` exports.

## How It Works

Each skill follows the same battle-tested workflow:

```
Step 1 — INPUT GATHERING
  Fetch URL · Request screenshots (HARD STOP) · Confirm readability

Step 2 — CONTEXT DETECTION
  Language commit · Brand snapshot (internal) · Audience calibration

Step 3 — 11-CATEGORY SWEEP
  Walk every category · Check against framework · Mark state per category

Step 4 — ICE SCORING
  Score every finding · Sort by priority · Calibrate to category defaults

Step 5 — DELIVERY
  Samenvatting · Category sweep · Findings · Test roadmap · Limitations

Step 6 — EXPORT
  .docx (client report) · .xlsx (sprint planning)
```

### Why screenshots are mandatory

CRO findings based purely on HTML are unreliable. Modern web stacks render content dynamically via JavaScript — product cards, reviews widgets, trust badges, customer logo carousels, chat widgets, A/B test variants, conditional content — none of it shows up in raw HTML.

**Every skill enforces a hard stop:** no audit happens until screenshots are provided. This prevents fabricated findings and protects audit credibility.

## Output Example

Every audit follows the same structure. A snippet of what a finding looks like:

```markdown
### 🔴 Trust signals — Geen reviews above-the-fold op B2C product page

**Diagnosis**
Visible in screenshot: de productpagina toont alleen één Trustpilot-logo
in de footer; geen review-aggregate, geen ster-rating bij het product,
geen customer-quotes. Per Spiegel Research Center converteren producten
met zichtbare reviews 270% beter dan zonder. Voor mid-price B2C ecom
(€50-200 range) waar visitors first-time-buyer-anxiety hebben...

**Recommendation**
1. Plaats aggregate review-rating (★ 4.7 — 234 reviews) direct onder
   product-titel above-the-fold
2. Voeg 2-3 reviewer-quotes toe in dedicated reviews-sectie...

**Test specification**
- **Hypothesis:** "Als we aggregate reviews above-the-fold tonen, dan
  stijgt add-to-cart rate aanzienlijk doordat first-time-buyer-anxiety
  wegvalt (Spiegel Research Center; Cialdini social proof)."
- **Primary metric:** add-to-cart rate
- **Expected impact:** +15% to +30%
- **ICE:** I=9, C=9, E=8 → 8.7
- **Source:** Spiegel Research Center; Cialdini (Influence)
```

Each audit delivers 8–15 of these, sorted by priority, exportable to `.docx` for clients and `.xlsx` for sprint planning.

## Disclaimer

This kit is provided as-is. While tested across multiple verticals (luxury fashion, B2B SaaS, professional services, managed IT, marketplaces, ecommerce, consumer services) and languages, **edge cases may occur** — especially with unusual page architectures, single-page applications with heavy client-side rendering, or page-types not covered by the matrix.

The skills are conservative by design: they will not invent findings, will not claim missing elements without visual verification, and will not recommend risky disclosures (e.g. specific financials on B2B about pages). A manual review of each audit is still recommended before sharing with clients.

Expected-impact ranges are calibrated against research benchmarks (Baymard, CXL, Forrester) — not against the audited brand's own baseline. Always validate findings via A/B testing on real traffic.
